# Remotion 工作流改进提案

这份提案来自 XiHack 模板在 2026-09-20 至 2026-09-22 的连续迭代。它不是把本片的旋钮、新拟态或具体文字动效推广成通用审美，而是提炼一条能复用于其他 Remotion 项目的制作与验收流程。

## 结论

现有工作流值得优化，而且重点不应是再建立一套组件框架。更高收益的方向是补齐“从创意判断到最终载体验收”的生产链：

1. `yoru-motion-research` 继续保存参考、运动研究、规则与明确批准的范例。
2. 全局 Remotion skill 负责项目级制作流程、工具选择与最低验收门槛。
3. 每个成片仓库用 `REFERENCE-LOCK.md`、内容契约和检查记录保存本片特有决定。
4. 已停放的 `yoru-motion-system` 暂不作为新流程的主入口，也不在本轮顺手重构。

## 建议的八阶段流程

### 1. 真实盘点

- 先确认仓库、分支、未提交改动、Composition、依赖、素材、字体、音乐与最终播放环境。
- 明确哪些是参考库、哪些是当前实现、哪些仓库已经停放，避免在错误的层级投入。

### 2. Reference Lock

- 在写视觉代码前记录已批准方向、明确拒绝项、可探索项和证据来源。
- 区分“用户举的例子”和“用户要求精确复刻的规格”。灵感可以替换，硬边界不能擅自改变。
- 为关键镜头写清最终稳定构图；动效必须服务于它，而不是让动画结束后仍留有倾斜、漂移或难读状态。

### 3. 能量曲线与章节动作词

- 先定全片能量曲线，再为每章指定一个动作性格，例如：建立、收紧、释放、聚焦、证明、收束。
- 动作词描述叙事作用，不绑定某个效果组件。例：`收紧` 可以是异向聚拢，也可以是遮罩压缩。
- 不平均分配特效。保留安静章节，才能让少量 2.5D、满幅展开或空间接力有效。

### 4. 内容契约先于视觉精修

- 把可替换字段、人数、条目数量、媒体类型、裁切入点和文字容量写成机器可检查的契约。
- Studio 与 preflight 共用同一份校验；“检查通过”必须与“可以进入预览”含义一致。
- 视频条目使用自己的局部时钟，避免第二、第三段素材在出现前已经播放。

### 5. 只隔离高风险机制

- 只为不确定且影响大的机制建立测试 Composition，例如旋钮物理感、复杂遮罩或相机运动。
- 已确定的普通文字入场直接在主片实现，避免测试片与主片时序长期分叉。
- 新依赖必须有明确收益；短暂 2.5D 优先使用帧驱动的 CSS perspective / transform，真正需要相机、灯光和遮挡关系时再引入 Three.js。

### 6. 统一时间源

- 章节边界、场景起点、点击帧、声音、进度标尺和背景状态都从同一时间源派生。
- 动画使用帧和 Composition 的 `fps`，不使用 CSS transition、wall-clock 时间或随机状态。
- 为文字保留稳定阅读段；不要让“进入”占满整段内容时间。

### 7. 最小但完整的验收梯

按以下顺序检查，上一层失败时不继续做昂贵导出：

1. TypeScript / lint 与内容 preflight。
2. 每个关键改动只抽“进入中段 + 稳定态”两类决定性帧。
3. 对复杂动效生成连续帧条，排查跳变、重叠和过早透明。
4. 输出一段正常速度的短预览，交给设计者判断节奏；慢放好看不算通过。
5. 只在关键接缝通过后做一次完整 MP4。
6. 用 `ffprobe` 验证编码、尺寸、帧率、音轨、时长和文件大小。
7. 从最终 MP4 本身重新抽帧，不以 Studio 或 still 代替最终载体。
8. 在最终载体检查中文、英文、数字、标点和重点字重是否发生字体 fallback；发现 fallback 必须修复后再交付。

这条验收梯贯彻“尽可能少做测试”：不是铺开主题矩阵，而是只检查会改变判断的接缝和最终载体。

## 审美批准与技术通过分开

建议每轮都明确两个状态：

- **Technical pass**：代码、内容契约、媒体计时、字体、声音与最终 MP4 均符合规格。
- **Creative approval**：设计者以正常速度观看后，认可节奏、手感、信息层级和整体气质。

技术通过不能冒充视觉批准；反之，短预览看起来顺也不能替代最终 MP4 验收。

## 建议保留的项目产物

- `docs/REFERENCE-LOCK.md`：当前视觉边界与取舍。
- `docs/OPTIMIZATION-PLAN.md`：按文件执行的改动清单。
- `docs/REVIEW.md`：每轮实测证据、最终载体信息和未完成边界。
- `scripts/preflight.mjs`：内容与媒体入口检查。
- `review.mjs` 或同类脚本：由时间线生成决定性帧，而不是手抄一批容易过期的帧号。
- 一段只包含本轮关键变化的正常速度预览，供审美确认；不把它误称为最终成片。

## 何时进入 Gold / 范例库

只有满足以下条件后，才把项目或镜头提升为通用范例：

- 用户明确批准，而不仅是“达到及格水平”或“技术上可用”。
- 已在真实内容和真实素材下使用，而不是只在占位数据下成立。
- 版权、字体、音乐和可再分发边界清楚。
- 范例说明提炼的是可复用原则，而不是复制 XiHack 的旋钮、配色或文案。

## 建议写回的位置

若要正式升级已有工作流，优先把“八阶段流程”和“最小验收梯”写入全局 `video-motion/remotion-best-practices` skill；把已经批准的代表镜头和研究结论留在 `yoru-motion-research`。本轮只在当前项目记录提案，没有跨仓库修改或推送工作流源码。
